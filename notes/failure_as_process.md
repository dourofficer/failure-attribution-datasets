## Description

- **Purpose.** An empirical study (RQ1–RQ4) that treats a coding-agent failure as a **temporal process** with three annotated timestamps — t_err (decisive error), t_lock (lock-in: outcome empirically unrecoverable given the agent's later behaviour), t_obs (first observable failure signal) — plus the triggering mechanism (root cause), post-lock-in behaviour and fabrication. It is not framed as an attribution benchmark, but t_err is exactly a step-level "decisive error" label and the data support "when did it go wrong / could it have been caught" analyses.
- **Construction (natural failures).** Terminal-Bench (240 containerised CLI tasks; Terminal-Bench 2.x via Harbor) × 3 scaffolds (MiniSWE = mini-SWE-agent, OpenHands, Terminus2) × 7 frontier models (Claude Sonnet 4, GPT-5, Gemini 2.5 Pro, Qwen3-Coder-480B, DeepSeek-V3.2, Kimi-K2-Instruct, Devstral 2). Raw pool 3,843 completed runs; only tasks with all 21 scaffold×model runs are kept → 89 tasks × 21 = 1,869, minus 75 failed executions → **1,794 trajectories (1,184 FAIL, 610 PASS), 63,276 steps** (one step = one agent turn: reasoning + action). Outcome = Terminal-Bench hidden tests.
- **Annotation.** LLM-assisted pipeline: Claude Opus 4.6 drafts a structured JSON annotation with verbatim evidence quotes (≤25 words per step index; the long-trajectory sampling rule reads steps 1–40, every 5th step, and the last 30 when m > 120); then two of four human annotators independently review the full trajectory and finalise every label; disagreements resolved by discussion. **Inter-annotator agreement:** weighted κ = 0.95 / 0.94 / 0.96 for t_err / t_lock / t_obs, categorical κ = 0.83 root cause (trigger), 0.80 awareness, 0.78 tail behaviour, 0.90 fabrication (shipped in `docs/kappa_agreement/kappa_results.csv`, recomputable from `dual_annotations.csv`). The codebook (`docs/CODEBOOK.md`) notes that the shipped JSON is the output of "one LLM annotator per trajectory"; the paper states all final labels are human-verified.
- **Labels (FAIL schema):** `t_err`, `t_commit` (= t_lock), `t_surface` (= t_obs, null for 28 % silent failures) with `*_evidence` quotes and `timepoint_confidence`; `trigger_mechanism` (9-way root cause) + `trigger_explanation`; `primary_failure_layer/category/subtype` and `contributing_failure_1_*` (open-vocabulary), `root_cause_label`, `one_sentence_failure_summary`; `forewarning_*` (signals before lock-in: command_error, empty_or_unexpected_output, repeated_command, contradictory_evidence, self_doubt_language); `awareness` (never_aware / aware_wrong_fix / aware_abandoned / aware_too_late), `first_awareness_step`, `num_recovery_attempts`; `tail_dominant_behavior` (verification_theater, thrash_repeat, immediate_claim, fabrication, new_wrong_direction, cosmetic_progress); `fabrication_present/type/onset_step/evidence`; `verification_ever`, `first_relevant_verification_step`; `action_segments` = contiguous `[start, end, code]` runs with codes E/P/W/X/V/C/R/O; `long_traj`, `uncertain_fields`. **PASS schema:** `num_error_events`, `first_error_step`, `num_recoveries`, `max_detour_length`, `near_miss`, `verification_before_claim`, `suspicious_pass` (+type), `solution_directness` (direct / detour / trial_and_error), `one_sentence_strategy_summary`.
- **Root-cause taxonomy (Table II, trigger at t_err):** *Epistemic* (57.9 %): false premise 30.7, specification neglect 14.9, output misreading 4.4, ignored signal 4.1, premature action 3.7 · *Competence* (32.8 %): knowledge gap 24.0, capability limitation 8.8 · *Environment* (9.4 %): environment blocker (mishandled) 8.8, other 0.6.
- **Task formulation & results.** Not an attribution leaderboard. The paper's 14 findings include: median t_err = 7, t_lock = 12, t_obs = 16 (half of failures commit the decisive error by step 7); median fix window 1 step (60.9 % ≥1, 43.9 % ≥3, 239 runs >10); a **prefix monitor** (Claude Sonnet 4.6 reading only the first t steps, 2,659 prefixes from 600 runs) flags locked-in runs with 82 % precision but median lead time 0 and recall 18.2 % → 28.8 % when given the task requirements; post-lock-in tails: repairs the wrong problem 24 % of runs / 39 % of wasted steps, keeps repeating 15 % / 29 %, verification theatre 28 % / 15 %, fabricated success 15 % / 13 %, gives up 18 % / 4 %; epistemic errors dominate in every one of the 21 systems (44–80 %); pass rates 19–45 %.

## Schema (files)

- `data/traj_data_v2_all89tasks.json` — list of 1,794 records; `case_id` = `<task>__<scaffold>__<model>`; a record is FAIL iff it has `t_commit`; fields as listed above (FAIL vs PASS schema). `data/v2_annotations/<case_id>.json` — the same records, one file each.
- `data/merged_tasks.json` — 89 tasks: `task_id`, `category` (16 values), `difficulty` (easy/medium/hard), `task_type`, `core_requirements_summary` (list), `raw_task_ref` / `solution_ref` (GitHub URLs into terminal-bench).
- `data/case_studies_annotations.json` — 18 full records for the paper's case studies (adds `_case_study_group/_label`, `_task_*`).
- `data/pass_error_observability.json`, `data/pass_obs_input.json` — LLM-confirmed observability labels for PASS-run errors; the latter contains ~3-step command/output excerpts (`context`) around the first error for 433 PASS runs (the only raw step text in the release).
- `docs/kappa_agreement/dual_annotations.csv` — per-item labels of annotators A and B for the 1,184 failures; `docs/CODEBOOK.md` — full schema, vocabularies with realised frequencies, invariants C1–C16 and the verbatim annotation prompts.

## Notes for the report

- **Annotation-only release.** The main caveat: no step text, so the dataset cannot be used directly to *evaluate* a step-localisation method; it can be used for meta-analysis of where decisive errors fall (t_err median 7, relative position median 0.31) and of the fix window / observability lag, or re-joined with the public Terminal-Bench trajectories (CodeTracer release) to rebuild the corpus.
- **Three timestamps instead of one:** the decisive error (t_err) vs. lock-in (t_lock) vs. first observable signal (t_obs) distinction is unique among the surveyed datasets and is exactly the "could an online monitor have caught it" question; note t_obs can precede t_lock (observability lag is negative for some runs).
- **Taxonomy mixes mechanism and open vocabulary:** `trigger_mechanism` is the controlled 9-way label (use this); `primary_failure_layer/category/subtype` are free-form LLM-drafted strings (24 distinct "layers", 15+ categories) and should not be treated as a taxonomy.
- **LLM-drafted, human-verified labels** with unusually high κ (0.78–0.96) — high agreement is partly explained by both annotators starting from the same Claude draft.
- **Scale and balance:** the largest coding-agent failure corpus (1,184 failures across 21 systems, median 27 steps, max 1,189), with both PASS and FAIL runs for the same 89 tasks, which allows paired success/failure comparison that the other datasets lack.
- **Overlaps:** same Terminal-Bench/Harbor ecosystem as other terminal-agent benchmarks; conceptually related to TrajAudit (coding-agent failure diagnosis) and to TrajErrBench's SWE-Bench Pro subset, but no shared trajectories.
