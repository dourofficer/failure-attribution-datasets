\section{Observability and replayability of the released data}\label{app:obs}

\paragraph{Purpose} The research proposals of the companion document \code{proposals.pdf} need two properties that the overview table (Table~\ref{tab:overview}) does not show: how much of the execution each release \emph{records} per step, and whether the state at a step can be \emph{restored and re-executed}. This appendix ranks the 21 datasets on both. The ranking is read from the dataset sections (Sections~\ref{sec:g1}--\ref{sec:g4}) and refers to what is actually downloadable as of October 2026, not to what the paper describes.

\paragraph{Observability tiers}
\begin{itemize}[leftmargin=1.1em]
\item \chip{good}{A} every LLM call's full input and output, tool I/O and (where it exists) environment state or screenshots;
\item \chip{s1}{B} the complete message stream with tool calls and tool returns, but not the per-call inputs or the state;
\item \chip{warning}{C} agent outputs only (no tool inputs, no observations beyond what the agent printed);
\item \chip{critical}{D} no step text released.
\end{itemize}

\paragraph{Replayability tiers}
\begin{itemize}[leftmargin=1.1em]
\item \chip{good}{A} replay tooling ships with the data (recorded prefix or runnable agent code plus environment);
\item \chip{s1}{B} public environment and public agent code, so a prefix can be restored and re-executed (the $\mathrm{Roll}(\cdot)$ of the companion proposals document) in principle;
\item \chip{warning}{C} only some subsets are replayable, or the authors' pipeline is demonstrated but not released;
\item \chip{critical}{D} live web or no agent code: only the recorded trajectory exists;
\item \chip{ink3}{E} nothing released.
\end{itemize}

\paragraph{Reading the ranking} Rows are ordered by the two tiers together, observability first. Two points follow. The measured programme of Proposal~1 in the companion document is feasible only on the rows whose replay tier is A or B (rows 1--3, 5--7, 12 and, with the trajectories rebuilt, 19), which coincides with the systems of that document's data-engine table. The output-only group (rows 15--18) is also the group with the lowest or unreported annotator agreement (Section~\ref{sec:reco}), which is what one expects when the annotator cannot see the evidence needed to place the step.
